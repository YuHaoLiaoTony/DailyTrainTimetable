- 使用者端讀 `latest.json`／日期檔會拿到過期時刻表，等同資料集失效 3 個月。

## 根因

- **已確認**：08-23 之後沒有任何成功的排程 run 產出資料，`latest.json` 的 `availableDates` 停在 08-22。
- **未確認**：為什麼停止（TDX 額度／憑證失效、`schedule` 被 `disabled_inactivity` 停用、程式或測試失敗）。Actions run 歷史在記錄當下不可得，**需人工查 `gh run list --workflow update-train-data.yml` 的歷史紀錄**補齊。
- **已確認的結構性缺口**（無論上述哪一種）：
  1. workflow 沒有 `if: failure()` 回報，失敗完全靜默。
  2. keepalive 步驟與抓取在同一個 workflow，該 workflow 被停用時 keepalive 一起停，無法自癒。

## 已採取的矯正

- `.github/workflows/staleness-alert.yml`：每小時檢查已發布資料，過期就開／更新 `data-staleness` issue 並讓 workflow 失敗。
- `update-train-data.yml` 新增 `if: failure()` 回報步驟，失敗時開／更新 `workflow-failure` issue；成功時自動關閉。
- `.github/workflows/keepalive.yml`：keepalive 獨立成自己的 schedule，主 workflow 被停用時仍有備援 push。
- 排程改為 `--days 31`，降低「資料集只有 1 天」的退化風險。

## 不放棄的部分與已放棄的部分

- **已放棄**：08-23 ~ 11-16 的 87 天缺口，現有程式（只從執行當下的台北日期往後產生 N 天）無法補回，也不再補。
- **維持**：只保證「今天之後」的資料持續更新；資料集**不保證連續**，冷啟動或快取失效後只會有從當天起算的 N 天。
